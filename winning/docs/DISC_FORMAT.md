# Mega-CD 『ウイニングポスト』光碟格式

KOEI，Mega-CD（系統區 `1993.JUL`、序號 `GM T-76044`）。只有 Mega-CD 版（MD 沒有卡帶版）；內容是 SFC 版（`~/works/superfamicom-re/winning`，1993.03）的移植：表格相同，改成大端序、加 pad、文字改 Shift-JIS，頭像改成未壓縮的 MD tile。映像：`roms/megacd/Winning Post (Japan).7z`（Redump，Track 01 MODE1/2352＋音軌）。程式碼在 `cd.py`。

## 1. 光碟檔案

| 檔案 | 內容 |
|------|------|
| `SMAIN.PRG` | 主程式，副 CPU，載入 PRG-RAM `$C000`；人物名、馬主、調教師、部位表、調色盤等（指標是 PRG-RAM 位址，減 `$C000` 就是檔內位移） |
| `ORGKAO.DAT` | 頭像：208 格 × 1,024 bytes（960 bytes tile＋64 bytes 0），接著是合成臉的部位圖與指標表（§3） |
| `SNDAT.DAT` | 騎手記錄等 |
| `UMAKAO.DAT` | 馬的頭部圖（未解） |
| `EVENT.DAT` 等 | 未解 |

## 2. 人物

| 表 | 位置 | 格式 |
|------|------|------|
| 人物姓 | `SMAIN.PRG` `0x56274` | 256 個 BE32 指標 |
| 人物名 | `SMAIN.PRG` `0x55E74` | 256 個 BE32 指標 |
| 馬主 | `SMAIN.PRG` `0x43F56` | 41 × 24 bytes：BE16 臉碼、+5 姓（7 bytes）、+12 名（7 bytes）、+19 冠名 |
| 調教師 | `SMAIN.PRG` `0x4432E` | 30 × 22 bytes：BE16 臉碼、+2 所屬騎手 − 20、+5 個性、+8 姓、+15 名 |
| 騎手 0–19 | `SNDAT.DAT` `0x760` | 20 × 24 bytes |
| 騎手 20–69 | `SNDAT.DAT` `0x2B0` | 50 × 24 bytes |

- 文字：Shift-JIS；`ESC K`／`ESC H` 切換半形假名為片假名／平假名（預設平假名）；外國騎手的姓用半形片假名，`-` 是長音。
- 騎手記錄是 SFC 版的 22 bytes 加 2 個 pad（+15、+19）：BE16 臉碼、BE16、3 bytes、0、…、+23 人物編號（姓名查人物表）。
- 與 SFC 版（原版）比：馬主 41、調教師 30、騎手 70 筆的臉碼與姓名全同；人物表只有 110 的名字不同（「信也」，SFC「伸次」；不是騎手，匯出不受影響）。

## 3. 頭像

40 × 48 pixel = 5 × 6 個 MD tile（4 bpp，高位 nibble 在左），由左上依列排列。臉碼 0x00–0xCE 是頭像，0xCF 是秘書（有馬桜子），其他（bit 15）是合成臉。

| 範圍 | 內容 |
|------|------|
| `ORGKAO.DAT` 格 0–207 | 頭像 0x00–0xCF；色號與 SFC 版的頭像逐 pixel 相同 |
| 位移 `208 × 1024` 起 | 合成臉部位圖：8 型 × 4 版 × 960 bytes（每版是一整張臉，部位從同位置的格取）；與 SFC 版的部位圖色號相同 |
| 格 238 | 部位圖的指標表（32 個 BE32，`$80000 + n × 0x3C0`，遊戲把 16 磁區載到 Word RAM `$80000`） |

畫臉的程式（副 CPU）：

- `$18C6A`（x, y, 臉碼, VRAM tile, CRAM 列）：臉碼 < 0xCF 呼叫 `$12366`（讀 `ORGKAO.DAT` 一格到 `$62AC0`），其他呼叫 `$18A6E` 合成；`$6423E` 記上次的臉碼，相同就不重讀；最後 `$18BAC` 選調色盤。
- 合成（`$18A6E`）：類型 = bits 14–12，部位 = bits 1–0（上半，格 0–14）、3–2（下半，格 15–29）、5–4（零件A）、9–8（零件B）。零件A／B 各一段：`SMAIN.PRG` `0x43A44` 每型 6 bytes = 兩組（起始格、寬、列數），從該版的同位置格複製。
- 和 SFC 版的差異：類型 5 的零件A 是格 11–13、16–18，零件B 是 21–23（SFC 版零件A 11–13，零件B 16–18、21–23）。沒有人物用類型 5。
- 秘書臉在初始化時（`$F194` 呼叫 `$12366`）載到 VRAM tile 0x2B0，對話框用 CRAM 第 0 列（調色盤 3）。

### 調色盤（`$18BAC`）

6 組，依 SFC 版的編號：

| 編號 | `SMAIN.PRG` | 用途 |
|------|------|------|
| 0 | `0x42F84` | 合成臉類型 0–3 |
| 1 | `0x42FA4` | 合成臉類型 4–7 |
| 2 | `0x42EE4` | 頭像 0x28–0x9C |
| 3 | `0x42F04` | 頭像 0x9D–0xA7、0xB6–0xC4；秘書 0xCF |
| 4 | `0x42F24` | 頭像 0x00–0x27、0xC5–0xCE |
| 5 | `0x42F44` | 頭像 0xA8–0xB5 |

和 SFC 版的差異：0x9D（騎手 小原四郎）SFC 版用調色盤 2，CD 版用 3。顏色是 MD 的 9-bit 值，換算用 MAME 的色階（`cd.LEVELS`），與其他 MD 資料集一致。

## 4. 驗證（Genesis Plus GX，`tools/gpgx.py`）

| 腳本 | 內容 | 結果 |
|------|------|------|
| `verify_cd_faces.py` | 新遊戲的初期設定玩到選調教師的畫面存檔；每個臉碼：在 `$18C6A` 停下改臉碼參數、清掉 `$6423E`，按 C 顯示詳情，比對 VRAM `$BAC0` 起 960 bytes 與 CRAM 第 3 列；秘書臉比對 VRAM `$5600` 與對話框的 CRAM 第 0 列 | 頭像 208／208、合成臉 72／72（馬主 40 個碼＋每型 4 個部位輪換的碼），tile 與調色盤全同，約 15 秒 |
