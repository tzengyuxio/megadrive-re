# MD 大航海時代 ROM 格式

ROM：`Daikoukai Jidai (Japan).zip`，1 MB（1,048,576 bytes），SHA-1 `a4552b23079b161da9ad47ac7cb9c4ecb3731967`。
表頭 `SEGA MEGA DRIVE (C)T-76 1992.FEB`、國內名 `大航海時代`（SJIS）、海外名 `UNCHARTED WATERS`、序號 `GM T-76053 -10`。表頭的 checksum 是 `0x7004`，從 `0x200` 起算出來的是 `0x38FB`，兩者對不上。

整體來說，這是 FC 版（`~/works/famicom-re/daikoukai`）和 SFC 版（`~/works/superfamicom-re/daikoukai`）的資料改寫成 68000 的 C 結構：big-endian、16 位元欄位對齊到偶數位址、名字的位移改成 32 位元的 ROM 指標。文字編碼和頭像像素沒有改，整份 ROM 沒有壓縮。下文的位址，`0x…` 是 ROM 位移（等於 68000 位址），`$FF….` 是 RAM。

## 1. 文字

和 SFC 版相同，都是 JIS X0201 半形假名：`0xA1–0xDF` 是半形片假名；預設當平假名顯示，遇到 `ESC K`（`1B 4B`）改成片假名，`ESC H`（`1B 48`）切回平假名。`0x2D` 是長音，`0x0A` 是換行，`0x00` 是結尾。對應的函式是 `rom.text()`。

序幕和部分畫面的文字不在這套字串裡（例如序幕的「わたしのあいぼう、ろうこうかいし」），推測是另一套字型或圖形，**尚未解開**。

## 2. 初始資料區塊（`INIT` 0xE3E48 → `$FF1000`，0x121B bytes）

開新遊戲時，memcpy `$0688` 會把整塊複製到 `$FF1000`（大約在第 1769 幀）。`$37B2` 是 memset。下表的位移以區塊開頭（`$FF1000`）為準。

| 位移 | 大小 | 內容 |
|------|------|------|
| `+0x000` | 0x36 × 20 | 每筆 0x36 bytes。到リスボン時，每筆的 +9..+11 會被改寫（推測是行情），**未解** |
| `+0x5DE` | 10 × 41 | 人物：0 是主角，1–20 是航海士，21–40 是提督 |
| `+0x778` | 18 × 21 | 艦隊：bytes 0–3 是位置（chunk x、chunk y、metatile x、metatile y），其餘**未解** |
| `+0xCFE` | 16 | 主角名，預設「レオン」。人物 0 的名字指標指向 RAM `$FF1CFE` |
| `+0xD0E` | 10 × 21 | 能力：主角＋20 位航海士。bytes 0–5 依序是年齡（推定）、統率、判断、知力、勇気、強さ；bytes 6–9 **未解**。主角在分配點數時會重擲 bytes 1–5 |
| `+0x112E` | 70 | 各港的建物旗標 |

### 人物記錄（10 bytes）

| 位移 | 內容 |
|------|------|
| 0–3 | BE32 名字指標。指向 ROM；主角指向 RAM `$FF1CFE` |
| 4 | 戰鬥等級 |
| 5 | 航海等級 |
| 6–7 | BE16 頭像碼（見 §4） |
| 8 | 旗標。高 4 bits 是國籍，索引國名表（§3）；低 4 bits 目前全是 1 |
| 9 | pad |

`$65CE(person)` 回傳人物記錄的指標。

## 3. 其他名稱表

- **國名** `0xD76E0`：4 個 BE32 指標，依序是 ポルトガル、イスパニア、イスラム、かいぞく。`$5984` 用這張表取國名。提督 36–40 的國籍是 3（かいぞく）。
- **女性** `0xE506C`：20 個 BE32 名字指標。第 k 位女性用專屬頭像 k + 13：`$8266` 的 mode 2 會把 code 加上 0xD，這點已在程式裡確認。
- **港口** `0xE5946`，20 bytes × 70。內容是 15 bytes 港名，接著 chunk x、chunk y、metatile x、metatile y 各 1 byte，再加 pad。0–49 是交易港，50–69 是補給港。
- **港口屬性** `0xE5EBE`，6 bytes × 50（只有交易港）。依序是經濟圈（0–7）、特產品（索引商品表）、byte2（**未解**）、道具（0xFF 代表沒有，推定）、byte4（**未解**），最後是 pad。
- **名稱表**都是 BE32 指標陣列：

| 表 | 位址 | 數量 | 讀取它的程式 |
|----|------|------|------|
| 商品 | `0xE653A` | 26 | `$D9E6` 等 6 處 |
| 砲 | `0xE65A6` | 3 | `$2C844` 等 3 處 |
| 船首像 | `0xDA3F2` | 6 | `$2CFF0`、`$2D036` |
| 船種 | `0xDA43A` | 6 | **沒有直接引用**，推測是從其他表的基底加位移讀取，尚未確認 |
| 木材 | `0xDA482` | 4 | `$2F028` |
| 桅 | `0xDA492` | 3 | `$2F0EE` |
| 帆 | `0xDA49E` | 2 | `$2F170` |

另有一份商品名表 `0xD9EAC`，指向 `0x3BB3A` 起的另一組字串，內容相同，沒有採用。

上述內容（人物 41、女性 20、名稱表、港口 70 與港口屬性）解出來都和 SFC 版完全一樣。

## 4. 頭像

頭像都是 5 × 6 tile（40 × 48 像素），packed 4bpp，每張 960 bytes，tile 依列優先排列。全部共用一組 16 色色盤 `FACE_PALETTE` `0xDBF0C`，由 `$386F4` 載入 palette line 0。

畫頭像的入口是 `$8266(x, y, code, mode)`：

- `mode & 0xF`：
  - 0：code 是人物編號，取人物表第 code 筆的頭像碼；code 為 0xFF 時改用頭像 8。
  - 1：code 本身就是頭像碼。
  - 2：女性，頭像碼 = code + 13。
  - 3：特殊處理。
- 頭像碼 ≤ 0xFFF 時走 `$8068`，畫專屬頭像；大於 0xFFF 時走 `$AE36` → `$ACFC`，畫組合臉。
- `$3873E` 把 tile 傳到 VRAM tile 0x200 + 30·slot。

另外，`$9B4E(code, mode)` 是設施說話者的頭像 helper，固定畫在 (2, 21)，共有 68 個呼叫處。

### 4.1 專屬頭像

`PORTRAITS` `0x44AC6 + 960·n`，n = 0–52，沒有標頭。0 是主角，13–32 是女性，33–52 是航海士。

### 4.2 組合臉（頭像碼 > 0xFFF）

- 頭型 = `code >> 10 & 3`。
- 5 個 slot 各取 4 頁中的一頁，複製順序是 bottom（`code & 3`）、top（`>> 8`）、eyes（`>> 6`）、nose（`>> 4`）、mouth（`>> 2`）。後複製的部件會整格蓋掉先前的 tile。順序與 SFC 版相同。
- `COMPOSITE_ADDR` `0xD7F66`：每個頭型 0x50 bytes，也就是 20 個 BE32，依 top、eyes、nose、mouth、bottom 的順序，每個部件 4 頁。
- `COMPOSITE_TILES` `0xD80A6`：每個頭型 0x14 bytes，對同樣 5 組各記一個（起始 tile、tile 數），都是 BE16。

### 4.3 沒有人物使用的專屬頭像（1–12）

這些頭像由固定的頭像碼畫出來：

| 頭像 | 用途 | 依據 |
|------|------|------|
| 1–3 | 國王 | 王宮程式 `0x2442E`：侍從說「へいかが おあいに なられるそうでございます」（`0x3CA5E`）之後呼叫 `$9B4E(港號 + 1, 1)`，港號存在 `$FF44A6`。港 0–2 依序是リスボン、セビリア、イスタンブール，對應國名表的前三國。頭像 1 也出現在「よくぞもどった、ところでおうじょは?」 |
| 4 | 施設（推定為道具屋） | 和「どれが ほしいんだね?」（`0x3B79C`）、「どれを うりとばそうってんだい?」（`0x3B81C`）、「どのくにのじょうほうだね?」（`0x3B72C`）一起出現。ROM 裡找不到店名，所以不給名字 |
| 5 | 造船所 | 只在 `0x6570` 被呼叫；選單有「ぞうせん」「しゅうり」（`0x3EBC4`），也有「うちじゃあ、ぞうせんはやってないよ」 |
| 6 | 交易所 | 相場、投資的對話；字串「こうえきじょ」 |
| 7 | 酒場 | 酒、看板娘的對話；字串「さかば」 |
| 8 | 老航海士 | 序幕第 3 張臉，台詞是「わたしのあいぼう、ろうこうかいし。」；在リスボン給建議的也是他。也是 mode 0 且 code 為 0xFF 時的預設頭像 |
| 9 | 港 | 實機進港時會呼叫 `$9B4E(9, 1)`（返回位址 `0x1E19A`）；字串「みなと」（`0x3B5D8`） |
| 10 | 王宮 | 陛下的侍從、金幣寄存「おあずけですか」；字串「おうきゅう」 |
| 11 | 宿屋 | 「おくのへやで どうぞ」（`0x3B5A8`）、「おつかれでしょう」，選單有「しゅくはく」「じょうほう」；字串「やどや」 |
| 12 | クリス王女 | 序幕第 2 張臉，台詞是「クリスおうじょ・・・」 |

序幕在 `0xFCBE` 呼叫 `$8266(5, 6, code, 1)`，code 依序取自 `0xD85AA` 表：0、0x0C、8、0。

### 4.4 與 SFC／FC 版比對

- **SFC 版**：專屬頭像 53/53 與組合臉 20/20 的色號完全相同（組合臉以本作 20 位提督的碼加上「同頁」碼比對）。色盤不同：SFC 是 BGR555，MD 是 9-bit。
- **FC 版**：頭像同樣是 40 × 48，編號 0–47 和 MD 的 0–47 指的是同一批人，但改畫成 NES 的 3 色＋子色盤，色號之間沒有一對一的對應。若對每張頭像找最好的「MD 色號 → FC 色號」對應，平均只能解釋 76% 的像素（最低 37%，最高 94%），所以是依同一份原畫重繪的。MD／SFC 比 FC 多出 5 張（48–52）。

## 5. 世界地圖

地圖檔在 `MAP` `0xE65FA`，內容與 FC 版 PRG `0x60000` 相同，欄位是 little-endian。`$847A` 會把讀到的 word 交換位元組順序，`$8440` 用 memcpy 讀取。

- 大小是 24 × 12 個 area，每個 area 有 3 × 3 個 chunk；每個 chunk 有 7 × 7 個 block，等於 14 × 14 個 metatile、28 × 28 個 tile。全圖共 72 × 36 個 chunk，16128 × 8064 像素。
- `$858A(area x, area y)` 透過 `$84C2` 把一個 area 的 9 個 chunk（每個 49 bytes 的 block id）載入 `$FF44C8`，查表方式與 FC 版相同（`rom.chunk_blocks`）。
- `$86E8` 把 chunk 畫到 plane A（`0xE000`）的第 33–60 列、第 2–29 欄，步驟如下：
  - block 由 `MAP_BLOCKS` `0xD7894` 查出 4 個 BE16 metatile id（左上、右上、左下、右下）。
  - metatile 的位址是 `MAP_METATILES` `0xD7774 + 0x48·set + 4·m`，內容是一個 BE32 指標，指向 4 個 BE16 name table word（目前看到的都用 palette line 3）。4 個 set 指向的是同一批 18 個 metatile。
  - set 存在 `$FF3A8A`，依 area 列決定，順序與 FC 版相同：`[3, 2, 1, 1, 0, 0, 0, 0, 1, 1, 2, 3]`。
- **tile**：`MAP_TILESETS` `0xD7AC6` 有 4 個 BE32 指標，每個 set 一組 72 個 tile，放在 VRAM tile 0x286 起。每組 tile 前面的 BE16 是 `0x0286`。
- **色盤**：`$926A` 從 `MAP_PALETTES` `0xD7AD6 + 0x18·set + 4·phase` 取 16 色，載入 palette line 3。phase = (`$FF1CDA` / 30) % 6，推測對應時段；phase 0 和 3 的色盤相同。
- 畫面上，plane A 的 x 起點是 16，y 會依捲動而變（實測看到 −24、−8、8）。
