# MD 三國志II ROM 格式

KOEI，1991 年 10 月，Mega Drive。檔案 `roms/Sangokushi II (Japan).zip`（1 MB，SHA-1 `d9a912caacaa476a890564f62b6ce9cc8f60496e`）。

本文的偏移一律是 **ROM 偏移**，也就是 68000 位址（ROM 映射在 `$000000–$0FFFFF`）。RAM 位址寫成 `$FFxxxx`。多 byte 數值都是**大端序**。

這是 SFC 版スーパー三國志II（`~/works/superfamicom-re/san2`）的姊妹移植：劇本、人物、配置、州、相鄰、戰場這些資料表和 SFC 版**內容相同**，只是換成大端序，部分記錄加寬（§9 對照表）。欄位意義沿用 SFC／FC 版的結論，再用 MAME 在 MD 上重新驗證。

## 1. 硬體與引擎

| 項目 | 內容 |
|------|------|
| 標頭（`0x100`） | `SEGA MEGA DRIVE (C)T-76 1991.OCT`；國內名稱 SJIS「三國志Ⅱ」，海外名稱 `ROMANCE II`；`GM T-76023 -10`；checksum `7B0E`；ROM `0–0xFFFFF`；SRAM `0x200001–0x20FFFF`（奇數位址）；地區 `J` |
| 向量 | SSP `$FFF000`、RESET `$000200`、VBlank `$001130` |
| 引擎 | 68000 機器碼，看起來是 C 編譯的（有 `link`／`unlk` 框架），**不是** SFC 版那種 p-code。反組譯用 `tools/m68k.py`（MAME dasm） |
| 畫面 | H32（256 寬）；plane A、B 都在 VRAM `0xE000`（32 × 32），window `0xF800`；VSRAM 垂直捲動 8，所以截圖的 y = 列 × 8 − 8 |
| 操作 | C 是確認，A 在指令畫面叫出地圖。Y/N 提問：← 是 Y、→ 是 N（A／B／C 無效）。數字輸入從 `00` 開始、游標在十位：↑↓ 改數字、←→ 換位數、C 確認 |
| MAME 色階 | 3-bit 色階顯示成 0、52、87、116、144、172、206、255（非線性，從截圖對出，`rom.LEVELS`） |

操作序列（frame 時序）在 `tools/session.py`：劇本選擇、君主選擇、指令畫面、開戰。

## 2. 劇本標頭與州（41 州）

**劇本標頭** `0x48DA2`：6 × 20 bytes，年 BE16（顯示年 − 1），其後 18 bytes 未知。

**州** `0x48E7A + 1394 × 劇本`，每劇本 41 × 34 bytes（SFC 是 25 bytes；前面多了指標空間）：

| 偏移 | 內容 |
|------|------|
| 0–15 | 執行期指標（人物串列） |
| 16、18、20 | 金、兵糧、人口（BE16） |
| 22 | 勢力（`FF` = 空白州） |
| 23–27 | 執行期（載入後 `+25` 會改成 `0x40`） |
| 28–32 | 土地、民忠、治水、馬、信 |
| 33 | 補齊 |

246 筆（6 × 41）和 SFC 版逐欄相同。劇本載入後整段複製到 RAM `$FF2712`。

**相鄰表** `0x5255A`：41 × 6，1 起算，`FF` = 無；slot d 與 5 − d 是相對的六角邊（同 SFC）。**大地圖游標格** `0x4B112`：8 × 9，0 起算州號。

## 3. 字型與文字

**字型** `0x55896`：16 × 16 1bpp，每字 32 bytes = 4 個 8 × 8 tile（左上、右上、左下、右下），每 tile 8 bytes、一 byte 一列、MSB 在左。和 SFC 版排法相同。

- 碼 c < `0x85F0`：字形在 `0x55896 + (c − 0x8140) × 32`。
- c ≥ `0x85F0` 是跳脫碼：程式 `$4560` 用 16-bit 運算 `(c << 8) + 0xC0C0` 換算，`85F1` 實際代表 `0x8300` 的位置（蒯）。
- 讀字形的指令在 pc `0x45A0`（模擬器讀取追蹤找到）。
- 字碼依讀音排序：`8141` 阿、`8142` 逢、`8143` 安…，和 SFC 版的碼不同，但人名用到的 387 個碼和 SFC 的碼**一對一**，字形 387/387 逐點相同（含 `85F1` ↔ SFC `837C` 蒯）。

漢字碼對照 `data/kanji_ext.json` 由 `tools/build_kanji_map.py` 從 SFC 版的對照表推出（同一人、同一位置的字對應，再核對字形），屬外部資料，所以匯出欄位是 `[EXT]Name`。

選單／訊息文字（「どこへ せめこみますか」之類的假名訊息）的編碼與位置**尚未解**。

## 4. 人物（352 人）

### 4.1 姓名 `0x4C8D4`，352 × 16 bytes

| 偏移 | 內容 |
|------|------|
| 0–6 | 漢字碼 BE16，最多 3 字，`00` 結尾 |
| 7–15 | 讀音，cp932 半形片假名，`00` 結尾（SFC 是 8 bytes） |

讀音 352/352 和 SFC 相同。ROM 有 17 人用了替代字或截短。kaodata 資料集的 `name` 照 ROM 原文，其中 16 人另給史書寫法 `nameHistorical`（`export_kaodata.py` 的 `NAME_HISTORICAL`；辛毘／辛毗只是異體，依 kaodata 準則不填）；讀音也照 ROM。`persons.csv` 同樣是 ROM 原樣。

### 4.2 人物 `0x4BB14`，352 × 10 bytes

| 偏移 | 內容 |
|------|------|
| 0–3 | 義理、人德、野望、相性 |
| 4–5 | 親族 BE16（位元旗標） |
| 6 | 生年 |
| 7 | `00`（補齊） |
| 8–9 | 頭像碼 BE16（§6），和 SFC 版相同 |

**能力** `0x4DED4`：352 × 3（才智、戰力、號召），和 SFC 逐 byte 相同。
**忠誠** `0x4B2D4`：352 × 6（每劇本一 byte，`FF` = 不在場），和 SFC 相同（審榮在劇本 2 也是 85）。

### 4.3 配置 `0x4F786`，352 × 22 bytes

和 SFC 版相同，只是 16-bit 欄位改成 BE16：`+0` 登場年、`+1` 未知、`+2–7` 每劇本所在州、`+8` 人物編號 BE16、`+10–21` 每劇本 BE16（同州串列與旗標 0x80 君主、0x20 在野、0x10 初期兵 50）。352/352 和 SFC 換序後相同。身分與初期兵士的推法同 SFC 版；少數猛將的兵士由載入程式另外加到 20／30／50（劇本 1 有 10 人、劇本 2 有 4 人，和 SFC 相同）。

劇本載入後，RAM 裡每人一筆 24 bytes（劇本 1 從 `$FF1052` 起）：

| 偏移 | 內容 |
|------|------|
| 0–3 | 同州下一位的指標 |
| 4–5 | `00 00` |
| 6–8 | 知、武、魅 |
| 9 | 勢力（`FF` = 在野） |
| 10 | 忠誠 |
| 11–13 | `FF` |
| 14–15 | 兵士 BE16 |
| 16–17 | 兵士 × 10 |
| 18 | 訓練 |
| 20–21 | `00 06` |
| 22–23 | 人物編號 BE16 |

## 5. 大地圖

- tilemap `0x68900`：28 × 18 個 BE16 plane entry，遊戲畫在 plane cell (2, 3) 起。
- tile `0x1D0–0x380` 依序存在 `0x652E0`（4bpp，高 nibble 在左）。
- 調色盤 `0x4E3B4`：CRAM 第 0 組。
- 州號 tile `0x1C0–0x1CF` 在 `0x68CF0`，執行期蓋在地圖上；勢力是另外畫的旗子，不像 SFC 版改地圖顏色，所以 ROM 圖就是畫面上的底圖。
- 君主選擇畫面會暫時改 CRAM 第 0 組（山林變淡），驗證改用開戰選州的畫面。

## 6. 頭像

40 × 48 = 5 × 6 個 4bpp tile，以列為主序，每張 960 bytes。MD tile 格式：一 byte 兩點，高 nibble 在左。

**專屬頭像**（碼 1–208）：連續存放在 `0x71D8E + (碼 − 1) × 960`，不分 bank。調色盤編號（0–3）在 `0x515C6 + 碼 − 1`，和 SFC 相同。圖和 SFC 版轉換後相同，只有 11 張不同（碼 9、62、67、92、93、96、100、107、111、120、186），是 MD 版重繪的。

**組合臉**（碼 bit 15 = 1），程式在 `$65D0`：

- bit 0–2 是頭型 h。ROM 裡的存放位置 s 和 h 不同：h 0↔2、1↔3 對調（h < 2 → h + 2，2 ≤ h < 4 → h − 2，4–7 不變；`rom.stored_head`）。
- 頭型的 4 筆記錄在 `0xA928E + s × 0xF00`，每筆 960 bytes。
- 每個區域用 2 bit 選記錄：上（bit 3–4）、下（5–6）、眼（7–8）、鼻（9–10）、口（11–12）。bit 13–14 是調色盤（4 組頭像調色盤之一）。
- 部件表 `0x45340 + s × 6`：眼、鼻、口的起始欄，再來是三者的寬度；眼、鼻、口各在第 2、3、4 列。
- 「上」「下」是部件以外、分界 cell 前後的格子：上區是 cell 0–14（3 列），s = 3（頭型 1）是 cell 0–9（2 列）（程式 `$668C`）。SFC 文件寫「頭型 3 例外」，是以存放位置計的同一件事。

**調色盤** `0x4E2F4`：4 組 × 16 色，MD 格式 `0000BBB0GGG0RRR0`。遊戲把袁術的臉放在 VRAM tile `0x420–0x43D`、CRAM 第 2 組。

驗證：`verify_kaodata_export.py` 在君主選擇畫面把袁術的頭像碼改成每個碼（人物用到的 352 個＋32 個涵蓋所有頭型、記錄、調色盤的合成碼），讀畫面、VRAM、CRAM 比對，384/384 相符。頭型對調、上區 cell 數、調色盤 bit 都由這步確認。

## 7. 戰場地圖

- `0x47A1A`：41 張 × 78 bytes，每張 13 欄 × 12 列六角格，每格 4 bit（高 nibble 在前），以列為主序，和 SFC 相同。地形：0 平地、1 森、2 林、3 山、4 河、5 村、6 城。
- **畫面**：每格六角占 2 × 2 tile，第 c 欄、第 r 列的左上角在 plane cell (3 + 2c, 3 + 2r + c mod 2)。
- **地形 tile 表** `0x48AB6`：7 地形 × 4 個 BE16 plane entry（左上、右上、左下、右下），用到 tile `0x1C0–0x1DB`；河用調色盤 1，其餘調色盤 0。
- **tile 圖**：
  - `0x1C0–0x1CF`（平地～山）在 `0xB0A8E` 起依序排列（`0x1C8`、`0x1C9` 和 SFC 稍有不同，其餘轉換後相同）。
  - 河 `0x1D0–0x1D3` 是動畫：tile n 的第 j 格在 `0xB0C8E + 32 × (4n + j)`，匯出用第 0 格。
  - `0x1D4–0x1DB`（村、城）在 `0xB0E8E`（SFC 版是村城在前、河在後）。
- **調色盤**：CRAM 第 0 組 `0x4E4F4`、第 1 組 `0x4E574`。
- 進軍點：攻方的 5 個進場格右上角換成 tile `0x1F3`，在 hex 11、12、24、25、38（和 SFC 相同，從州 19 進攻）。
- 開戰時讀的就是 ROM 裡的那一張（把州 20 的資料在 ROM 裡換掉，畫面跟著變）。
