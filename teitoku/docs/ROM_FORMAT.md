# MD 提督の決断 ROM 格式

`roms/Teitoku no Ketsudan (Japan).zip`：1 MB，表頭 `SEGA MEGA DRIVE (C)T-76 1992.JUN`、`提督の決断 / P.T.O.`、`GM T-76073 -00`。偏移都是 ROM 偏移（= 68000 位址）；RAM 位址寫成 `$xxxx`，指 `$FF0000–$FFFFFF` 內的偏移。

程式是 SFC 版（`~/works/superfamicom-re/teitoku`）用 68000 C 重寫：表格、文字編碼、劇本差分的欄位和 SFC 一一對應，只是記錄放寬、改成 big-endian、指標改成 32-bit。SFC 版的格式說明是很好的對照（`superfamicom-re/teitoku/docs/ROM_FORMAT.md`）。

## 1. 引擎與操作

- 畫面 256 × 224（H32），plane A／B 共用 `$E000` 的 64 × 64 name table：plane A 不捲動，plane B 往下捲 256 列（VSRAM = `$0100`），所以第 0–27 列是 A（文字、視窗），第 32–59 列是 B（地圖等背景）。
- 函式用 C 呼叫慣例（參數由右到左 push、呼叫端清 stack）：`$4DB8` memmove(src, dst, len)、`$450E` 未壓縮 tile 送 VRAM（src, 第一個 tile, tile 數）、`$56C6` KOEI LZ 解壓送 VRAM（src, 第一個 tile, …）、`$4548` 調色盤送 CRAM。
- 操作序列（`verify_scenarios.py`）：標題 `w2400 start start` → C（新しくゲームを始める）→ 劇本清單（down）C → 玩家人數（up → 1 人）C → 陣營（預設日本軍）C → 難度 C → Y/N C（這時載入劇本）→ 情勢、勝利條件 C C → 予算（START、C C、B → Y/N C）→ 将校データ：20 名將校逐一 C（決定）＋ C（Y）→ 主畫面。

## 2. 字型與文字

- 字型 `0x53386`：1036 個 16 × 16 1bpp 字（32 bytes：左上、右上、左下、右下 8 × 8），和 SFC 字型 `0x118000` 只差第 1035 字；字表沿用 superfamicom-re 的 `data/charset.txt`（複製在 `data/charset.txt`）。
- 編碼同 SFC：兩 byte 碼 0x8140 + g；0x9140 + k 代表 0x8200 + 0x100 k；一 byte 碼是 ASCII、JIS X 0201 假名（平假名顯示；`ESC K` 之後片假名，`ESC H` 回平假名）；`ESC F` 切換日期字（`0`/`1`/`2` → 年月日）。字串 NUL 結尾，指標是 32-bit ROM 位址。

## 3. 初始化資料與劇本

- C runtime 啟動時（`$39F6` 呼叫 `$4DB8`）把 ROM `0x7A9B6` 起 `0x3F89` bytes 複製到 RAM `$0060–$3FE8`；開新遊戲時再複製一次。這就是**劇本 1** 的資料。
- 劇本選單（`$110D6`）把劇本號寫進 `$0062`、`$0064`（word），之後呼叫載入程式 `$10B46`（D3 = 劇本；≤ 1 就不改），`$10FCC` 返回。
- 劇本 2–9 的差分記錄**沒有壓縮**（SFC 是 LZ）：指標表 `0x60EA2 + 4 × 劇本`。記錄配置：

| 偏移 | 內容 | 寫到 |
|------|------|------|
| `+0` | 艦船 270 × 16 bytes | p0 → +5；p5–pB → +A–+10；+14 word = (舊值 & 0xB800) \| p.w[0xE] |
| `+0x10E0` | 艦隊 32 × 28 bytes | +0–9；p.w[A] = 提督號（陣營內 1 起算）→ +C 指標；+10–13、+16–17、+1A 旗艦（p.w[12] 艦號 → 指標）、+1E–22、+33、+34；+0 bit 15 = 不使用時其他欄位清為 FF／0 |
| `+0x1460` | 基地 50 × 38 bytes | +1–5、+6–19、+26、+2B–2D（人口 0 時友好 = 0x32）、+40–45、+48 word = (舊值 & 0x3800) \| p.w[0x24] |
| `+0x1BCC` | 陣營 2 × 52 bytes | +8–2E、三個基地號 → +30／34／38 指標、+3C 司令部、+3E–3F、+42 |
| `+0x1C34` | 日期 3 word | `$0074`（昭和年、月、日） |
| `+0x1C3A` | 提督旗標 40 bytes | OR 進提督 +22 |
| `+0x1C62` | 他國 12 bytes × n | +4–8；+9–D 五個值（上限 99）；之後 +C ≥ 0x50 → +E \|= 1、+C ≥ 0x5F → \|= 2、+C 與 +D 都 ≥ 0x50 → \|= 8 |

最後把兩陣營司令部（陣營 +3C，1 起算）的基地 +46 設為 2。`Rom.scenario_image` 照這個流程重建，`verify_scenarios.py` 比對 9 劇本 `$0060–$3FE8` 全部 16265 bytes。

9 個劇本：日米交渉決裂（S16.11.1）、真珠湾攻撃（S16.12.8）、珊瑚海海戦（S17.5.7）、ミッドウエイ海戦（S17.6.5）、ソロモン海戦（S17.8.8）、南太平洋海戦（S17.10.26）、マリアナ沖海戦（S19.6.19）、比島沖海戦（S19.10.23）、大和特攻（S20.4.7）；選單字串指標表 `0x60DD6`（`n:標題  Syy.mm.dd`）。

## 7. 陣營（68 bytes）、提督（36 bytes）、他國（16 bytes）

- **陣營**：+1 名稱（「日本」「連合国」）、+30／+34／+38 三個基地指標（推測作戦目標）、+3C 司令部基地（1 起算）；其餘未解（`sides.csv` 附原始 bytes）。
- **提督**：+0 姓名（NUL 結尾，日本軍漢字、姓名間有對齊用的空白，如「宇垣   纒」「山本 五十六」；盟軍片假名）；+22 旗標：低 5 bit = 指揮的艦隊號、bit 7 = 不登場、bit 5／6 外國籍（推測，同 SFC）。能力在開局亂數產生，不在 ROM。
- **他國**：+0 名稱指標；+4 同盟（1 日本 2 連合 3 中立）；+5 對日、+6 對連合；+7、+8 未解；+9–+D 五個值（未解）；+E 旗標（推測 bit 0 レーダー、bit 1 新型戦闘機、bit 3 長距離爆撃機）。

## 8. 與 SFC 版資料的差異

逐欄比對劇本 1–9 的解碼結果，幾乎完全相同。差異：

- 艦名 7 處（如 MD「ウエストバージニア」／SFC「ウエスト・バージニア」、MD「ラングレイ-」／SFC「ラングレイ5」）。
- 搭載数 2 艘（ボイス、ヘレナ：MD 0、SFC 4）；リュース的艦級 MD 85、SFC 83。
- 基地上限存成 byte 99（SFC 100）；ヨコスカ、トウキョウ、ノモンハン的座標稍有不同。
- 提督姓名保留對齊空白（SFC 也有，kaodata 兩邊都去掉空白）。

## 9. 頭像

`$9E00(提督指標, x, y, 頭像號)`：n = 提督指標非 0 時取提督號，否則用參數；n = 0x2A／0x31 再隨機加 {0, 2}（表 `0x5FD44`），0x2B／0x32 隨機加 {0, 2, 3}（`0x5FD48`）；n < 54 才畫。

- 圖：long 指標表 `0xAAB34`，54 個 KOEI LZ 串流（`tools/koei_lz.py`；MD 解碼器沒有查表，解碼時把 SFC 的表區塊接在 ROM 後面，同 san3），各解出 960 bytes = 5 × 6 個 4bpp tile 逐列排，寫到 tile 0x3C0（VRAM `$7800`）。
- 調色盤：`0x5C41E + 32 × word(0x5FCD8 + 2n)`，進 CRAM 第 3 列。54 個調色盤的 color 0 都是黑；color 0 在畫面上透明（3 張頭像有幾個 color 0 pixel，會露出背景）。
- 0–39 = 提督 0–39（SFC 盟軍是 i + 7），40–46 日本的其他人、47–53 盟軍的其他人（= SFC 20–26、47–53，但 SFC 23／24、50／51 對調）。其他人沒有名字，依服裝分組：40 陸軍、41 海軍、42 陸軍、43 飛行員、44 陸軍、45–46 飛行員；47 陸軍、48–49 海軍、50 飛行員、51 海軍、52–53 飛行員。
- 第二個頭像函式 `$E652` 用調色盤表 `0x60A3A`、CRAM 第 2 列、tile 0x440；用途未查。
- 遊戲沒有玩家看得到的頭像碼，kaodata 不寫 `code`。

與 SFC 頭像比較（只看結構：每個 MD 色號對到最多的 SFC 色號、反之亦然，取兩方向一致率較小者）：40 名提督都是同一張畫（逐一比對，最像的都是對應的 SFC 頭像），但沒有一張完全相同，一致率 0.61–0.97、平均 0.88——MD 版重新點過（換色、改陰影）。和 PC-98 版平均 0.45，是不同的畫。

## 10. 世界地圖

情勢、勝利條件畫面的背景（`$9100`、`$FBC6`、`$39AC0` 載入）：

- tile：`0x890EA` 起未壓縮的 4bpp tile 0x140 個，送到 tile 0x580（VRAM `$B000`）。
- tilemap：`0xD973A`，32 × 16 個 word（調色盤第 2 列，tile 號是絕對值，沒有翻轉），放在 plane B 第 39–54 列（畫面 y 56–183）。
- 調色盤：`0x5C21E`（32 bytes，CRAM 第 2 列；就在頭像調色盤池 `0x5C41E` 前面）。

256 × 128 px（SFC 是 32 × 15 tile）。`verify_maps.py` 驗證 tile、tilemap 位置、CRAM 與畫面。
