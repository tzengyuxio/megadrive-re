# 太閤立志伝（MD）ROM 格式

位址是 1.25 MB ROM 的檔案位移（= 68000 位址）。標頭 `GM T-76123 -00`、日期 1993.APR，checksum 正確。程式是 C 寫的（`link A6`＋參數放堆疊，
long 參數只用低 word）：memmove `$7014(src, dst, len)`、word 複製 `$7048`、KOEI LZ 解壓 `$33BA(dst, src)`、tile 上傳 `$3A7A`、
tilemap 放置 `$DC0`。

資料是 SFC 版（`~/works/superfamicom-re/taikou`）的同一份，差別在 16 位元欄位改 big-endian、補齊到偶數位址（紀錄多出 pad byte，pad 全是 0）。
人物 713 筆的 Id、勢力、居城、身分、政略／戦術 Lv、6 能力、7 技能和 SFC 解碼逐欄相同；勢力 +0–21、城狀態 +0–2 也相同。各欄位的意義沿用 SFC 研究；
MD 這邊另外用遊戲程式驗證過的有：開始時資料的複製（`verify_scenarios.py`）、頭像（`verify_faces.py`）。

標「推測」的是沒有用遊戲程式驗證過的解讀；標「未解」的是還不知道。

## 1. 操作序列（MAME，按鍵按住 10 幀，之後一律放 20 幀，和 `tools/replay.py` 相同）

| 序列 | 到達 |
|------|------|
| `w1500 start:10 w200 start:10 w200` | 主選單（新たな物語を始める…；C 確定，A 取消） |
| `c:10 w300` | 選型畫面（`verify_scenarios.py` 在這裡讀 RAM） |
| `c:10 w300 c:10 w300` | 選型 → よろしい → 能力分配畫面（C 每按一次 +1） |
| `c:900 w100` | 50 點用完 |
| `a:10 w300 start:10 w300 c:10 w300 c:10 w300 c:10` | 確定 → 尾張地圖的開場事件；最後一個 `c:10` 之後才由名表讀藤吉郎的頭像碼，約 530 幀後頭像在畫面上（`verify_faces.py` 在最後的 `c:10` 後存 savestate） |

## 2. 文字

Shift-JIS：漢字、假名用全形，標點用半形（`A1` 。、`A4` 、），另有 ASCII `?!`、`\n`，NUL 結尾。解碼：cp932，半形片假名區 NFKC 再 NFC（`rom.sjis`）。
字串表都是 4-byte 指標 → NUL 結尾字串（§8）。

## 3. 名表（`0x85D22`，716 筆 × 16 bytes）

| 偏移 | 內容 |
|------|------|
| +0–6 | 姓（Shift-JIS，0 補滿） |
| +7–13 | 名 |
| +14–15 | 頭像碼 BE16（§6） |

名表的 index 就是人物 Id（人物紀錄 +0）。713–715 沒有人物紀錄。程式把 `0x85D30`（= 名表 +14）當表基底讀頭像碼（`$17642`）。
和 SFC 名表比，716 筆中 3 筆不同，都是 SFC 的錯字在 MD 改正：129 曼殊院覚如（SFC 叟殊院）、537 津田掃部助（SFC 挿部助）、556 箸尾高春（SFC 箱尾）。

## 4. 開始時資料

開機時與開新遊戲時，`$17D4x–$17E62` 先清 RAM，再用 memmove 把 6 段 ROM 複製到 RAM（`rom.INIT_SEGMENTS`；第一段用 word 複製 `$7048`）：

| ROM | RAM | 大小 | 內容 | SFC 對應 |
|-----|-----|------|------|----------|
| `0x7A8B0` | `$FF0040` | 0x140 | 未解 | `$203A–$2212` 的表 |
| `0x7A9F0` | `$FF0180` | 0x50 | 未解 | 同上 |
| `0x7AA40` | `$FF01D0` | 0x78 | 未解 | 同上 |
| `0x85A7A` | `$FF0248` | 0x2A8 | 勢力 20 × 34（§4.2） | `$2213` |
| `0x7B35E` | `$FF04F0` | 0x387C | 人物 241 × 60（§4.1） | `$24A7` |
| `0x7AAB8` | `$FF3D6C` | 0x8A6 | 城狀態 123 × 18（§5） | `$577D` |

另外清 `$FF4612`（0x5C4 bytes）。到選型畫面時 RAM 和 ROM 逐 byte 相同，只有城 68、72 的城狀態 +15 已被設 bit 4（`0x06 → 0x16`、`0x01 → 0x11`）。
SFC 的開始時區塊標頭 `$2000–$2039` 在 MD 沒有從 ROM 複製（`$FF0000` 起由程式設值，未解）。

## 6. 頭像

- 32 × 40（4 × 5 個 4bpp tile，列優先，640 bytes）。`$E36E(x, y, code, slot)`（wrapper `$E3BE` 多一個 flag，存 `$FF501E`／`$FF5020`／`$FF5644`）
  建好 tile 後上傳到 VRAM tile `0x260 + 0x14 × slot`，在 plane A（`$C000`，H32）放 tilemap，palette line 0。開場事件的頭像在格 (21, 13)，word `0x8260`。
- 調色盤：CRAM line 0 = ROM `0x8A2C0`（16 色）。色 0 透明（後面的 plane 透出）。
- 頭像碼 bit 15 = 0（`$E2F0`）：專屬頭像，KOEI LZ（`haouden/lz.py` 可解，遊戲解碼器 `$33BA`），指標表 `0x10AFD8` × 258。
- bit 15 = 1（`$E266` → `$E136(buf, code, t)`）：組合臉，型 t = bit 8–11（0–11）。
  - `0xD2FBE + 20 t`：5 個部位各（BE16 起始 tile、tile 數）；`0xD2BFE + 80 t`：5 部位 × 4 變化的長指標，指向未壓縮 tile。
  - 組圖順序：部位 4（變化 = bit 1-0）→ 部位 0（bit 7-6）→ 部位 1（bit 5-4）→ 部位 2（bit 3-2）→ 部位 3（**也是 bit 3-2**）；每段把連續的 tile 複製到 buf + 32 × 起始 tile，
    後面的蓋前面的。12 型的 5 段合起來都蓋滿 20 個 tile（buf 不清也沒有殘留）。
  - SFC 是 4 個部位（bit 7-6、5-4、3-2、1-0）＋ 20-bit 格 mask；MD 改成 5 段連續 tile，部位 3 和部位 2 共用 bit 3-2。
- 名表中 198 人用專屬頭像、518 人用組合臉；頭像碼和 SFC 名表 716/716 相同。專屬頭像用到 197 張（71 由 133 松平元康與 714 徳川家康共用），沒人用的是 43、119、120、134、180 與 202–257（共 61 張）。
- 呼叫 `$E36E` 的地方：`0x17660`（讀名表頭像碼）、`0x17868`（code 0x13）、`0x17926`、`0x179EE`、`0x19890`、`0x1A184`、`0x1AA40`、`0x1BA80`、
  `0x1BC6E`、`0x4356A`、`0x473DA`、`0x49062`、`0x4907C`、`0x5CF4A`；`$E432`（wrapper）。

### 和 SFC 頭像比較

- 專屬頭像 258 張：SFC 色 15（白）的地方 MD 都是色 1（每張約 140 px，頭像外框一帶），除此之外 236 張逐 pixel 相同；22 張不同（13、43、119、120、134、149、233
  各約 480–920 px 重畫，其中 43、119、120、134 是沒人用的頭像；其餘 15 張 1–9 px）。
- 組合臉：名表的 518 個組合碼合成後（色 15 → 1 同上）249 個和 SFC 相同；型 1、8、9、10 全同，型 0、2、5、6、7 全不同，型 3、4、11 部分不同
  （差異依型而非依 bit，是部件重畫，不是變化 bit 的排法不同；MD 的排法由 `verify_faces.py` 用遊戲程式驗證）。

## 7. 大地圖（只找到資料，未渲染）

- **區塊表** `0x764A8`：41 × 30 個 BE16 區塊號，和 SFC `0x5A911` 的表 1230/1230 相同（`$C0AA`、`$C250`、`$F5CA` 讀它）。
- **區塊格 byte**：ROM `0xC0826` 起未壓縮（`$17C22` 把位址存進 `$FFB460`），每區塊 64 bytes；和 SFC LZ 解壓後的 `0x8240` bytes 比有 489 bytes 不同（未逐一分析）。
- 格 byte → tile 的表、BG 字元與調色盤都還沒找；`export.py` 不輸出地圖。
