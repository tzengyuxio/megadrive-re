# MD 信長の野望・覇王伝 ROM 格式

KOEI，1993，MD。檔案 `roms/Nobunaga no Yabou - Haouden (Japan).zip`（2 MB）。偏移一律是 ROM 偏移（＝68000 位址），RAM 寫成 `$FFxxxx`，多 byte 數值皆 big-endian。資料結構幾乎照搬 SFC 版（`~/works/superfamicom-re/haouden/docs/ROM_FORMAT.md`），差別是指標由 2 bytes（WRAM 低 16 位元）變成 4 bytes（`$FFxxxx`）、word 改成 big-endian、並為對齊插入空 byte。「推測」表示沒有獨立驗證過。

## 1. 硬體與操作

| 項目 | 內容 |
|------|------|
| 表頭（`0x100`） | `(C)T-76 1993.DEC`，`GM T-76153 -00`，2 MB，checksum 正確 |
| 畫面 | H32（256 寬），plane 32 × 128 格 |
| MAME | `megadrij`，不需 BIOS |

**操作序列**（`tools/drive.py` 語法）：

- 到劇本選單：`w3000 start:10 w600 start:10 w600 c:10 w300`（標題前段太早按 start 會被吃掉）
- 選劇本：`down:10 w30` × s 次，`c:10 w600`（之後是「何人でプレイしますか」，游標在 1）
- 1 人 → 選大名畫面（游標在龍造寺隆信）：`c:10 w600`；再 `c:10 w600` 是確認框（顯示頭像）
- 確認框之後：「改名しますか」（`right:10 w60 c:10` 選取消）、電腦模式、等級、他国合戦、最後確認，各一次 `c:10 w600`

## 2. 壓縮

KOEI LZ，C 寫成的解碼器在 `$3C36(dst, src)`（取位元 `$3BBC`，遮罩表 `0x5C8F0`），和 MD 三國志III 相同；沒有 SFC 那種查表區塊。實作 `lz.py`。頭像（專屬與組合部位）都是個別的 LZ 串流。

## 3. 文字

- Shift-JIS，`00` 結尾。
- 外字：`EC8C EC8D EC8E` = 長宗我部、`EC8F EC8D EC8E` = 香宗我部（`rom.LIGATURES`）。
- 名稱表：long 指標表，各指到 `00` 結尾字串：

| 表 | 位址 | 筆數 |
|----|------|------|
| 國 | `0x5EBD6` | 64 |
| 官位 | `0x5E66E` | 226 |
| 家宝 | `0x5E9F6` | 120 |
| 合戦 | `0x5EDA8` | 15 |
| 能力名 | `0x5CED2` | 8（政治 戦闘 智謀 采配 野望 気合 勲功 知行） |
| 姫 | `0x74D58` | 93 |
| 地形 | `0x7B1DA` | 15 |

內容與 SFC 版相同；人名只有字形差異（蛎崎／蠣崎、尭煕／尭熙、頴娃／穎娃）。

## 4. 劇本

載入程式 `$1E2EE`：劇本號（`$FF001A` 的第一個 byte，1–3）查 `0x74D44` 的 long 指標表（`[1]=0x866EA`、`[2]=0x8DB46`、`[3]=0x94A80`），用 `$6276`（memcpy）把 0x6F3A bytes 複製到 `$FF001A`；再把共用區 `0x8D624` 的 0x522 bytes 複製到 `$FF6F54`。1582 年另外由 `$1E2D6` 設 `$FF72A4 |= 0x40`、`$FF72AC = 0xFF`。`rom.Rom.ram_image` 重現這個結果。

| RAM | 內容 |
|-----|------|
| `$FF001A–$FF01BB` | 開頭區（未解；第一個 byte 是劇本號，接著有一筆後登場人物記錄的複本） |
| `$FF01BC` | 大名 64 × 42 bytes（§4.3） |
| `$FF0C3C` | 人物 460 × 44 bytes（§4.2） |
| `$FF5B4C` | 城 110 × 42 bytes（§4.1） |
| `$FF6DD0–$FF6F53` | misc 區（未解） |
| `$FF6F54–$FF7475` | 共用區（未解） |

表之間用 RAM 位址（long，`$FFxxxx`）互相指，0 = 無。

### 4.1 城（42 bytes × 110）

| +0–3 | 未解（SFC +0） |

| +8–15 | 城名，最多 4 字（SFC +4–11） |
| +16 | 未解，全部 0（SFC +12） |
| +17 | 國 |
| +18–21 | 大名（大名記錄的 RAM 位址，0 = 無主） |
| +22 | bit 0–6 規模；bit 7 本城（推測） |
| +23 | 防 |
| +24–25 | 貫 |
| +26 | 未解（SFC +20） |
| +27／+28／+29 | 人、商、練 |
| +30／+32／+34／+36／+38 | 兵、銭、糧、鉄砲、馬（word） |
| +40 | 治 |
| +41 | 未解（SFC +35） |

城名 4 字：佐東銀山、吉田郡山、月山富田、尾山御坊、躑躅ヶ崎、佐渡国津、丹波亀山、大和郡山。SFC 文件把第 4 字（+10–11）當成未解欄位，其實是城名的一部分。

| +18 | 生年 − 1476 |

| +24–27 | 未解（SFC +22–25） |

| +29 | 未解（SFC +27；值與 SFC Rev 1 相同） |
| +30 | 未解（SFC +28） |
| +31 | 忠誠 |
| +32 | 低 4 位元 = 気合（開局時設定）；高 4 位元未解 |
| +33 | 空 |
| +34–35 | 人物 Id（= 頭像碼） |
| +36–37 | 知行（word） |

## 6. 頭像

40 × 48（5 × 6 個 4bpp tile，逐列 960 bytes）。`$7056(x, y, 頭像碼)` 組到堆疊上的緩衝區，`$4F32` 傳到 VRAM tile `$200`。調色盤只有一組：`0x5EE22` 16 色（CRAM 第 1 列）。

頭像碼 → 來源（`rom.Rom.face_source`，邏輯與 SFC 相同）：

| 頭像碼 | 來源 |
|--------|------|
| 0–0xD2 | 專屬頭像 12 + 碼 |
| 0xD3–0x36D | 表 `0x728E0`（以頭像碼為索引）的 word w：bit 15 → 專屬頭像 12 + (w & 0x7FFF)；否則組合臉，組 = `$6F44`（< 0x160：0、< 0x1EC：1、< 0x278：2、< 0x304：3、其餘 4），碼 = w |
| 0x36E–0x379 | 專屬頭像 碼 − 0x36E |
| 0x37A–0x391 | 組合臉，組 6（`$6F44` 對 ≥ 0x36E 回傳 6），碼 = 表 `0x72A3E`[碼 − 0x36E] |
| 0x392–0x397 | 專屬頭像 碼 − 0x24B |
| 0x398–0x399 | 程式沒有處理（用到未初始化的暫存器），不算有效頭像碼 |
| 0x39A–0x3A0 | 專屬頭像 碼 − 0x24D |

專屬頭像 n（0–347）：`0x1112C6` 的 long 指標表 → LZ 串流（`$7032`）。有效頭像碼共 927 個（專屬 348、組合 579）。

**組合臉**（`$6F9C(code, 頭像碼, buf)`）：5 個部位依序處理，部位 p：

- 款 v = (code >> 3·s) & 7，s = `0x5CCA8` 的第 p 個 word（0, 2, 3, 4, 1）
- 串流 = 部位 p 的 long 指標表（`0x113A86`、`0x116140`、`0x11704A`、`0x11776C`、`0x1181FE`；函式表 `0x5CCB2`）第 group × 5 + v 項
- 解壓到 buf + 32 × `0x5CC58`[group × 5 + p]（起始 tile），後面的部位覆蓋前面的

| 組 | 各部位起始 tile | 各部位 tile 數（同組各款相同） |
|----|----|----|
| 0 | 0, 10, 12, 18, 22 | 10, 20, 3, 1, 2 |
| 1 | 0, 15, 10, 15, 20 | 15, 15, 3, 2, 3 |
| 2 | 0, 10, 11, 17, 21 | 10, 20, 3, 1, 3 |
| 3、4 | 0, 10, 10, 16, 21 | 10, 20, 3, 1, 2 |
| 6 | 0, 25, 10, 16, 21 | 25, 5, 3, 1, 1 |

部位 0、1 合起來蓋滿 30 格（臉的上下兩塊），部位 2–4 是疊在上面的小塊。組 5 的表項存在，但沒有頭像碼會用到。

kaodata 資料集 `nobu5-md`：6 個 variant（= 組 0–4、6），slot `part0`–`part4` 各 5 款，item 是只含該部位 tile 的 40 × 48 圖（其他為 255）；348 張專屬頭像；817 個人物（人物 Id = 頭像碼）。

## 7. 驗證方法

- `verify_scenarios.py`：劇本選單存 savestate，各劇本選完後讀 RAM `$FF0000–$FF7475` 與 `Rom.ram_image` 比對。
- `verify_faces.py`：選大名畫面存 savestate，改 `$FF0D0E`（龍造寺隆信 +34）為每個頭像碼，按 C 開確認框，讀 VRAM `$4000` 960 bytes 與 CRAM 第 1 列。
- 欄位意義靠與 SFC 版解碼逐欄相同來佐證（SFC 版已用畫面對照）；MD 畫面沒有另外截圖對照。
