# MD エアーマネジメントII 航空王をめざせ ROM 格式

KOEI，MD，1 MB。`Air Management II - Koukuuou o Mezase (Japan).zip`（內含 `.md`，SHA-1 `6ed89fc3302023bc95c2bba0d45fe1d30e1c5d86`）：表頭 `SEGA MEGA DRIVE (C)T-76 1993.NOV`，國內名 `ｴｱ-ﾏﾈｼﾞﾒﾝﾄ2`（半形片假名），序號 `GM T-76143 -00`，地區 `J`，checksum 正確。

位址都是 ROM offset（＝68000 位址）；RAM 位址寫 `$FFxxxx`。數值一律 big-endian。

**和 SFC 版的關係**：資料表和 SFC 版（`~/works/superfamicom-re/airmanage2`，bank `$05`）逐值相同、排列順序也相同，只是改成 68000 C 結構（BE16 word、4-byte 指標、機種記錄補到 12 bytes）。用 SFC 解出的值當樣板在 ROM 搜尋即可定位各表。SFC 版有具名檔案表，MD 版沒有：頭像、調色盤、地圖都是程式裡寫死的絕對位址。

## 1. 程式與共通格式

- C 編譯（`link`／`unlk`、堆疊傳參），`$1D95E` 是 memcpy，`$1D984(vram_tile, count, src)` 把 tile 傳到 VRAM，`$1E3B4(src, …)` 載調色盤，`$C1A` 寫 tilemap。
- 文字：Shift-JIS（cp932），名稱是半形片假名單 byte，字串以 0 結尾；字串表是 4-byte 指標陣列。訊息文字（例：`0x44EB8` 一帶的機種推銷台詞）是全形、`0xFF` 分隔、`0x0A` 換行。
- 壓縮：地圖 tile 用 KOEI LZ，解碼器 `$3EB1A` 是 MD 光榮常見的「把查表寫成程式碼」版本，可直接用 `haouden/lz.py`（`rom.py` 以 `sys.path.append` 借用）。資料表與頭像沒有壓縮。
- VDP（本作畫面）：plane A `0xC000`、plane B `0xE000`（32 × 32 格）、sprite 表 `0xF000`、hscroll `0xF800`，H32（256×224）。

## 3. 劇本與開局狀態

4 劇本：1955／1970／1985／2000 年 4 月開始。劇本選單的名稱與年份範圍是**圖片**（`$7E58`：選單 tile `0x69FCE`，各劇本的標題圖 `0x6AA2A`、`0x6B6FC`、`0x6C366`、`0x6CFEC`，KOEI LZ），ROM 裡沒有字串；`rom.SCENARIOS` 的名稱是照畫面抄的（和 SFC 的字串相同）。

開局由 `$9D8E` 建立（在「以上の設定でゲームを開始します」確認前就建好；之後第一回合 COM 玩家行動會改第二記錄 byte 1）：

- `$FFA6F6` = 劇本編號 0–3；`$FF1FC4` = 從 1955 年 1 月起算的季數（開局 = 4 × (年 − 1955) + 1）。
- 都市記錄 `$FF2050`（89 × 4）與第二記錄 `$FF97A4`（89 × 2）：劇本 1／4 直接複製 A／B 表；劇本 2、3 的 byte 0 取 B，byte 1–3 與第二記錄 byte 0 由 `$9F6E` 插值：`a + trunc((b − a) × s / 3)`，夾在 0..255（s = 劇本編號），第二記錄 byte 1 清 0。byte 0 = 國家；byte 1–3、第二記錄 byte 0 意義未解（同 SFC）。
- memcpy：`0x4783C → $FF9964`（57）、`0x47D06 → $FF25B8`（192）、`0x47DC6 → $FF23F0`（228）、`0x48172 → $FF9858`（64）。
- `$A9A2` 把 `4 × 年 + 季 − 7820 ≤ $FF1FC4` 的世界事件先套用（`$29B86`）；實際效果等於「起始年以前」（起始年沒有第 0、1 季的事件），和 SFC 相同。

### 3.1 世界事件（`0x48914`，8 bytes × 55）

year BE16、quarter BE16（0 = 1 月）、message、target、type、value。事件數固定 55（`$A9A2` 迴圈到 0x37）。

- type 0：都市 `target` 的國家改為 `value`（例：1956 チュニス → チュニジア）。
- type 1：`$FF9964[target]` = `value`（國家表的值，意義未解）。
- message = 255 表示和前一筆一起顯示。

## 5. 地圖

兩種地圖都畫在 plane B，tile 從 VRAM tile 1 起，調色盤第 1 列，tilemap 32 × 22（entry 已含 tile 號與調色盤位元 `0x2000`），tile 號 − 1 = 串流中的 tile。

- **世界地圖**（`$3DF6`，開局與航路畫面、本社地區選單）：調色盤 `0x70022`（16 色）、tilemap `0x70042`（32 × 22 BE16）、tile `0x705C2`（KOEI LZ，704 tile）。
- **地區地圖**（`$40AE` 一帶，主畫面與本社都市選擇）：調色盤 `0x72634`（7 地區共用）、tilemap `0x72654`（32 × 23，7 地區共用，同 SFC `AR_MAP`；遊戲只畫 22 列、只載 704 tile）、tile 串流起點 `0x72C22 + 2 × offset`，offset 是 `0x72C14` 的 7 個 BE16（每地區 736 tile）。都市以 sprite 畫在 `0x47626` 的位置：tile `0x763` = 本社候選、`0x765` = 其他都市。
- 地圖畫面的下方幾列（584 格以後）會被訊息框、指令列覆寫。
- 本社地區選單在世界地圖上移動：ヨーロッパ 起，下 = アフリカ、右 = 中東、右右 = 東南アジア、右右下 = オセアニア、左 = 北アメリカ、左下 = 南アメリカ。

## 6. 頭像

- 40 × 48 = 5 × 6 個 4bpp tile（row-major），960 bytes 一張，無檔頭，原樣傳到 VRAM。

| kind | 位址 | 張數 | 內容 |
|------|------|------|------|
| 1 STAFF | `0xC0438` | 11 | 職員 |
| 0 SECRET | `0xC2D78` | 7 | 秘書 |
| 2 MAKER | `0xC47B8` | 6 | 製造商代表 |
| 3 MAYOR | `0xC5E38` | 5 | 國家代表（視窗印「％ｓ代表」） |

- 調色盤 `0xC0078`：30 組 × 16 個 MD 色（顏色 0 透明）。**第 0–3 組全是 0**（SFC 的國家代表用 0–3；MD 改用 26／12／8／16）。
- `0xC70F8`–約 `0xCD000`：四種的眨眼／說話動畫 tile（`$308E` 依 kind 載入多組；第一格就是頭像本身第 2、4 列的 tile）。另有幾張頭像的副本：`0xA775C`（MAKER 0）、`0xA7B1C`（MAYOR 0）、`0xA7EDC`（STAFF 0）、`0xA829C`（STAFF 7）、`0x69994`（MAKER 4），用途未查。
- 繪製 `$308E`：描述 (kind BE16, image, palette)。SECRET／STAFF 的調色盤取**目前玩家記錄 +0x23**（不看描述 byte 3），MAKER／MAYOR 取描述 byte 3。SECRET／STAFF／MAKER 載到 VRAM tile `0x2F0`（訊息框右側，CRAM 第 2 列），MAYOR 與部分 MAKER 載到 tile `0x6B0`（左側，CRAM 第 3 列）。
- **秘書**（`$9B34`，描述 `$FF22C4 + 4p`）：image = 0..6 隨機；palette = 本社地區基準 + 0..3 隨機，寫入玩家記錄 `$FFB2A4 + 36p + 0x23` 與描述 byte 3。**職員**（`$9BD0`，`$FF1F84 + 16p`，每人 4 名）：image 0..10 互不重複，描述 byte 3 不用（0／FF）。
- 地區基準：歐洲／大洋洲／北美 26、**非洲 12、中東／南美 8**、東南亞 16（SFC 是非洲 8、中東／南美 12——MD 對調了；`verify_faces.py` 把 4 家本社搬到各地區實測過）。
- **國家代表**（`$2D84C`）：image = 國家 % 5（`$40816` 取模），palette = 都市地區：歐洲／大洋洲／北美 26、非洲 12、中東／南美 8、東南亞 16（程式讀出，未在遊戲中觸發）。
- **製造商**：固定描述 `0x47C98`，12 家用 6 張圖。bae（調色盤 3）與ヤコブレフ（調色盤 2）指到空的調色盤，畫出來是黑影；兩家都不賣機種，遊戲中不會出現（kaodata 不收）。
- 設定畫面的引導人是 `0x4865A` = MAKER 圖 5、調色盤 25（＝ワールドリース 的描述）。
- 沒有內部的單一頭像碼，所以 kaodata 的 portrait 不寫 `code`。

### 和其他版本比對（只比色號結構）

- **SFC**：29 張圖（秘書 7、職員 11、製造商 6、國家代表 5）的 4bpp 色號逐像素相同；調色盤是重新配色的 MD 色（不是 SFC BGR555 直接換算）。
- **PC-98／DOS**（kaodata `air2-pc98`／`air2-dos`）：64 × 80、114 張，是另一套原畫，無法逐像素比對。

## 7. 操作（驗證腳本用，幀數從開機算）

`verify_scenarios.py` 的 `SCENARIO_MENU` → 劇本（下 3 幀一格）→ C（劇本）、C（YES）、C（難易度）、C（玩家數）→ 地區選單（世界地圖）→ C（歐洲）→ 本社都市畫面（游標起始 (128, 128)；`$FFB3C8/$FFB3CA` 直接寫入無效，要用方向鍵）→ 左 44、上 84、下 12 幀把游標移到ロンドン → C C → 「会社名を変更しますか？」右、C（いいえ）→「以上の設定でゲームを開始します」（`SETUP` 結束，開局狀態已建好）→ C × 5、C 後等 600 幀（世界地圖捲到本社，`GREETING` 結束）→ 下一個 C 秘書第一則訊息畫頭像 → 再 6 個 C 到主畫面（指令圖示列）。

## 8. 未解

- 劇本名、年份範圍是圖片，沒有解出字串（只照畫面抄）。
- 都市記錄 byte 1–3、第二記錄 byte 0 的意義；`$FF9964`（國家表）、`$FF25B8`、`$FF23F0`、`$FF9858` 的內容；`0x47875`、`0x47C8C`。
- 世界事件的 message 欄；機種 byte 10 旗標、生產終了年（推測）、價格規則（同 SFC）。
- 機種、關聯事業沒有在 MD 畫面另外驗證（表與 SFC 逐值相同；指令列哪個圖示是航空機發注未查）。
- 國家代表的描述規則只讀程式，未在遊戲中觸發驗證。
- 頭像動畫的格式（各 kind 的幀數、tile 對應）、頭像副本（`0xA775C` 等）的用途。
- 字型、訊息文字的完整表；機體圖、指令圖示等其他圖形。
