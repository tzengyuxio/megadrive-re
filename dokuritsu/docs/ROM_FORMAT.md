# Liberty or Death（MD）ROM 格式

位址是 2 MB ROM 的檔案位移（= 68000 位址）；RAM 位址寫 `$FFxxxx`。標頭 `GM T-76106 -00`、`(C)T-76 1994.MAY`、地區 U、SRAM 有。
程式是 C 寫的（`link A6` + 參數全放堆疊）：memcpy `$5F1E(src, dst, len)`、KOEI LZ 解壓 `$3C50(dst, src)`（工作區 `$FFD470`）、
未壓縮 tile 傳 VRAM `$4D06(src, 第一個 tile, tile 數)`、頭像 `$EE6A`。

這是 SFC 版独立戦争（`~/works/superfamicom-re/dokuritsu`）的移植：表與順序相同，2 byte 指標改 4 byte、LE 改 BE、記錄加寬、文字改 ASCII。
欄位意義多數沿用 SFC 研究。標「推測」的是沒用遊戲程式驗證過的解讀；標「未解」的是還不知道。

## LZ

KOEI LZ，`tools/koei_lz.py` 可解（MD 的解碼器沒有查表區，`rom.py` 把 SFC 的表接在 ROM 後面給解碼器用）。沒有總指標表，各類資料各有長指標：

| 指標 | 內容 |
|------|------|
| `0x10676A`、`0x10F498`、`0x117252` | 專屬頭像（見「頭像」） |
| `0x612DE` × 2 | HEX 戰場層 A（`0x5EE1A`）、層 B（`0x60520`） |

另有許多 128 bytes（4 tile）的 LZ 小圖指標表（`0x986A8` × 380、`0x98CA8` × 46、`0x12D238`、`0x1306BA`、`0xB6D9A` 等），用途未查。

## 人物（`0x5CAF2`，250 × 36）

順序與 SFC 相同（依姓氏排序；id 82 Gage、238 Washington）。

| 位移 | 內容 |
|------|------|
| +0 | 名（12，NUL 補齊；SFC 只有頭文字，MD 是全名） |
| +12 | 姓（15） |
| +27 | Health（体力） |
| +28 | Leadership（統率力） |
| +29 | Tactics（戦術力） |
| +30 | Discipline（指導力） |
| +31 | = SFC +29：bit 0–1 種別（未解），bit 2–7 未解 |
| +32 | = SFC +30（未解） |
| +33 | 0 |
| +34 | 頭像碼（BE16，見「頭像」） |

人物介紹頁（`$1C6DC(人物狀態指標)`）印 +28、+29、+30 與人物狀態 +6（Reputation），頭像 +34；`verify_persons.py` 逐人驗證。
能力與 SFC 不同的很多（体力 82 人、統率 61、戦術 200、指導 229）；種別、+31、+32、頭像碼 0 差異。

## 事件人物（`0x5C696`，44 × 24）

+0 名（10）、+10 姓（14）。記錄 k 用專屬頭像 `0x7D + k`（`$231C2`、`$1B59A` 等處 `addi.w #$7D`；Hancock = 記錄 19 = 頭像 144，大陸會議畫面確認）。
0–19 大陸會議（Samuel Adams … John Hancock）、22–41 英國（州總督 15 人＋Greville、Legge、Barrington、Sandwich、North），20、21、42、43 空白
（依 PC-98 同順序是兩邊的彈藥／糧食補給官，MD 畫面上叫 Quartermaster／Commissary）。頭像 169–173 沒有記錄（依 PC-98：傳令 2、海軍 2、傭兵隊長 1）。

## 地點（`0x5BFF6`，53 × 32）

| 位移 | 內容 |
|------|------|
| +0、+1 | = SFC +0、+1（未解） |
| +2 | 名（20） |
| +22 | 相鄰地點（8，`FF` 補齊） |
| +30 | = SFC +24：bit 0–1 地區（North／Central／South）、bit 2–5 州、bit 6 港（推測） |
| +31 | 0 |

全部欄位與 SFC 相同。

## 州

略稱指標 `0x61D10` × 15、全名指標 `0x61D4C` × 15：MA CD NH NY RI CT NJ PA DE MD VA NC SC GA FL（CD = Canada）。

## 1775 年劇本

「Start New Game」時 `$97EC` 用 memcpy 把 `0x5A946` 複製到 RAM `$FF000A`–`$FF16BA`（0x16B1 bytes，返回點 `$9810`）。另有 `$F75C` 只複製
前兩塊（載入存檔時？未查）。各塊和 SFC WRAM `$2009`–`$3DB5` 同順序：

| RAM | 內容 |
|-----|------|
| `$FF000A` | 0x50 bytes，未解（SFC `$2009`，0x47 bytes） |
| `$FF005A` | 13 × 6，未解（SFC `$2054`，13 × 5） |
| `$FF00A8` | 地點狀態 53 × 18 |
| `$FF0462` | 0x58 bytes，未解（SFC `$237B`） |
| `$FF04BA` | 陣營 2 × 54 |
| `$FF0526` | 人物狀態 250 × 18 |

**地點狀態**：+0 駐留人物串列頭（人物狀態指標，4）、+4 第二串列頭（未解）、+8 owner（未解）、+9 支持、+10 食糧（w）、+12 武器（w，推測）、
+14 弾薬（w，推測）、+16 未解（全部 100）、+17 0。

**陣營**（America、Britain）：+0 C-in-C（人物狀態指標）、+4 待機人物串列頭、+8 未解、+10 資金（推測，500）、其餘未解。

**人物狀態**：+0 下一人（指標，0 結束）、+4 地點（`0x35` = 待機）、+5 体力、+6 名声（Reputation）、+7 忠誠、+8 高 4 位元所屬（推測，同 SFC 分組）
／低 4 位元未解、+9 bit 0–1 階級（推測）／其餘旗標、+10–17 未解（= SFC +8–13，word 改 BE 再補 2 bytes 0）。

和 SFC 比：人物狀態只有 person 31 的地點欄不同（MD 15、SFC 16），其他欄位、地點狀態、陣營、所有串列都相同。

## 頭像

`$EE6A(-1, x, y, 頭像碼, slot)`：bit 15 = 0 是專屬頭像 n，n < 0x50 查 `0x10676A`、< 0x81 查 `0x10F498`、其餘查 `0x117252`（三張表都以 n 本身
索引），各是 960 bytes 的 LZ 串流（5 × 6 個 4bpp tile 逐列）；共 174 張，人物用 0–124，125–173 是事件人物。解到 `$FF5D50` 後傳到 VRAM tile
`0x684 + 30 × slot`。調色盤 `0x6200C`（16 色，全部共用），選陣營畫面在 CRAM line 2。

bit 15 = 1 是組合臉（`$EC82`）：bit 10–11 = 型 t；型表 `0x628B0 + 30 t` 是 5 個部位 ×（長指標、第一個 tile、tile 數），部位 tile 未壓縮，
變體 v = 指標 + 32 × tile 數 × v。依 4、0、1、2、3 的順序複製到臉的緩衝區，部位 p 的變體取 bit `PART_BITS[p]` 起 2 位元：

| 部位 | 寫到 | MD 讀的位元 | SFC 讀的位元 |
|------|------|------|------|
| 0 | 上 4 列 | 8–9 | 8–9 |
| 1 | 第 3 列 | 4–5 | 6–7 |
| 2 | 第 4 列 | 2–3 | 4–5 |
| 3 | 第 5 列 | 0–1 | 2–3 |
| 4 | 下 2 列 | 6–7 | 0–1 |

型 0 的部位 0 只複製 tile 數 − 5 個 tile，再把變體的 tile 20、24 放到臉的 tile 20、24。

和 SFC 比：專屬頭像 174 張像素相同（色號 8／14／15 輪換）；組合零件 80 張像素相同，但 MD 的型 1 = SFC 的型 2、型 2 = SFC 型 1，加上部位位元不同，
人物頭像碼雖然和 SFC 一樣，組出來的臉 125 人中只有 3 人相同（`verify_faces.py` 證實 MD 遊戲就是這樣畫）。

## 大地圖

`$DE70` 的地區 D4（0–2）：`0xC943C` 的長指標表 [D4] = 672 個未壓縮 4bpp tile（北 `0xB92FC`、中 `0xBEC3C`、南 `0xC403C`），`$4D06` 傳到 VRAM
tile `0x1C0`；表的 [3] = `0xBE6FC` 是 672 個 word 的 tilemap（`0x21C0 + i`，調色盤 1，28 × 24 逐列，三區共用），複製到 RAM `$FF62C0`。
畫在 VRAM `$F000` 的平面（寬 32 格），從格 (2, 2) 起。調色盤 `0x632EE`（CRAM line 1），水色 9–11 依 `0x6330E`、`0x6332E` 循環。

遊戲另外：
- 把外海的格子換成動畫 tile `0x658 + ((x + 2y) & 3)`（北 100、中 79、南 171 格；位置表未找到，那些 tile 幾乎全是色 0，中部有一格帶一個雜點）；
- 依擁有者把陸地色 15（白）改成 3／8／12，遮罩未解。匯出圖是上色前的白底、外海黑色。

## HEX 戰場（53 張，每地點一張）

`$A69E`／`$A6FE` 把 `0x612DE`／`0x612E2` 指的 LZ 串流解到 `$FF7FB0`，再依地點編號（`$C18E($FF0052)`）複製一張出來。資料和 SFC 的 entry 1／2
完全相同，只是以 BE word 存放（SFC 的 LE word 位元組對調）：

- 層 A：16 bytes 標頭 `LIBERTY_HEX_MAP\0`（也是 word 對調存放）＋ 53 × 336 bytes；層 B：53 × 336 bytes。
- 每張 14 × 12 格，每格一個 word，逐列。層 A：bit 0–3 地形 0–10、bit 4–7 與 bit 8–15 未解；層 B：河川／淺灘／海的 4 個 tile 編號 nibble
  （`8888` 一般、`FFFF` 無）。地形外觀名稱沿用 SFC 的推測（草地、森林、丘陵、山、河川、淺灘、未使用、海・湖、城鎮、要塞、柵欄陣地）。
- MD 的戰場 tile 與 tilemap 組法未查（沒有實際打到一場戰鬥）。

## 文字

ASCII，NUL 結尾。月份、序數在 `0x53F80` 附近；選單字（button／Option／Info.／Military／Personal）在 `0x540D0`；人物介紹在 `0x7509C`
（Washington）、`0x750B8`（Gage）。畫面上的 8 × 16 字：tile `2 × (c − 0x20)`（上半）、+1（下半）；名字另用比例字型畫進 tile。

## 操作序列（tools/drive.py 語法，機型 genesis）

| 目的 | 序列 |
|------|------|
| 標題 → Start New Game → Select game set-up | `w1600 start:10 w200 start:10 w300 c:20 w300`（`verify_faces.BOOT`；A 無效，用 C） |
| → Select side（Washington／Gage 的臉） | `c:20 w300` |
| → Washington 介紹頁 | `c:20 w300` |
| → Confirm C-in-C → Set Options → 結束選項 → Are these settings OK? → 大陸會議 | `c:20 w300 c:20 w300 start:20 w400 c:20 w600 c:20 w900` |
| 預算、援軍 → Who will you ask for support? | `c:20 w400` × 5（`verify_maps.CONGRESS`） |
| → 大地圖（北部）；按住下鍵捲到中部、南部 | `a:20 w400`；`down:120 w200`；`down:200 w300` |

VDP：介紹頁的 plane A／B／window 都在 `0xE000`（H32、32 × 32）；大地圖平面在 `0xF000`。
